AI 收藏夹 · MVP v1

本文档定位：一期 MVP 范围 final。围绕一个用户心智锚 + 一条主链路展开，其他全部砍到二期。

一、产品定位（一句话）

🎯 网页里看到的好东西，一键抓回来 —— 浏览器原生的元素级抓取 + 自动归类 + 可被找回。

二、用户主链路（唯一一条）

步骤 用户动作 系统响应
1浏览网页时发现好内容—
2点击地址栏「抓取」按钮 或 长按 C 键页面进入抓取模式：蒙层 + 元素识别 + 工具条
3单选 / 多选要抓的元素（图 / 段 / 视频 / 标题）被选中的元素加边框 + 工具条计数累加
4点「收藏选中」资产按类型自动分流入 4 个 Tab，自动生成摘要 + AI 标签
5打开 AI 收藏夹找回按 Tab / 标签 / 关键词检索（支持语义模糊匹配）

三、一期范围（4 个 PRD 单元）

编号 PRD 单元 一期范围 优先级
P01抓取能力地址栏按钮 + 长按 C 双入口；蒙层 + 元素识别（图 / 段 / 视频 / 标题）；单选 + 多选；自动分流入对应 Tab；ESC / 按钮退出；成功 toast + 跳转P0 核心
P02AI 收藏夹阵地三栏工作台（左导航 + 中流 + 右详情简版）；4 个 Tab：书签 / 图片 / 摘录 / AI 对话；列表态（默认）；搜索 + 标签筛选P0 核心
P03自动打标 + 摘要抓取后异步生成 200 字摘要 + AI 标签（≤5 个）；写入向量库；支持语义模糊检索P0 核心
P04书签 Tab 套壳 + AI 对话沉淀书签 Tab 套壳现有书签管理器；元宝助手内"沉淀此对话"按钮（自己提单加）P1

四、明确砍掉（二期再说）

砍掉项 理由
文件 Tab浏览器文件阵地已接得住，不抢自家业务
视频 TabPC 端仅 B 站 / YouTube 能拿到进度缩略图，体验不闭环；二期等 PC 自有播放器建好
文档 / 代码 / 音频 Tab伪需求 / 工程量大 / 浏览器场景使用频率低
元宝助手调起抓取依赖元宝团队配合，二期再接
关联推荐 / 主题模式高级功能，无核心心智支撑，二期再做
多选购物车 / 批量复杂操作MVP 阶段单选足够，复杂操作二期
瀑布流视图 / 按来源视图列表态默认即可，多视图二期
右侧详情面板放大态 / 主题模式详情面板一期保留基础形态，复杂态二期
站点白名单不预设站点，按通用 DOM 规则做兜底；主流站点适配优先级二期评估

五、4 个 Tab 详解（一期）

Tab 来源 展示内容
📚 书签地址栏 ⭐ / Ctrl+D / 抓取「标题」类型 / 旧书签管理器同步套壳书签管理器树状结构；列表态展示标题 + 来源 + 标签 + 时间
🖼 图片抓取「图」（含卡片）类型 / 网页右键 / 本地拖入缩略图 + 来源 URL + AI 标签；网页图存 URL + 缩略备份；本地存本体
✂️ 摘录抓取「段」类型 / 划词收藏文字片段 + 来源 URL + 抓取时间 + AI 标签
🤖 AI 对话元宝助手「沉淀此对话」按钮完整 QA + 引用 URL + AI 标签；沉淀即副本，元宝侧删除不影响

七、MVP 核心指标

指标 目标 / 验证
抓取按钮点击率≥ 5% PC DAU 至少触发过 1 次抓取（验证心智建立）
抓取成功率≥ 90%（抓取→入库→可见 全流程）
7 天复访率≥ 30%（抓取后 7 天内回 AI 收藏夹找过的占比）
语义检索准确率≥ 80%（用户能搜到自己抓过的内容）

九、风险

风险 应对
抓取能力工程量大 / 浏览器内核改动深已 ping steven 苏导确认可行性；如不能一期 ready，则一期降级为「书签 + 划词 + AI 对话」三个轻入口，抓取放二期
网页改版导致抓取失效不押站点白名单，走通用 DOM 规则 + 主流站点适配；抓取失败给清晰 toast 不强求
用户认知没建立 / 不会用抓取首次进入引导 + 案例卡 + 抓取按钮带 tooltip 提示
