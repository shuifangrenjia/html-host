1 · 战略对齐

为什么这件事必须现在做？

1.1 浏览器 0.4 主战场 · 大目标

2026 H2 浏览器核心命题：从"看网页的工具"升级为"承接用户记忆与行为的 AI 入口"。AI 资产专项是这个升级的核心载体。

1.2 AI 收藏夹的战略位

📍 三个层次
  1. 近期价值：补齐浏览器"用户主动留痕"的能力空白，提升 PC 端 DAU 与停留时长
  2. 中期价值：成为浏览器与元宝助手的共享记忆中枢——浏览器贡献场景化资产，元宝消费这些资产做个性化
  3. 长期价值：在 Agent 时代抢占"用户记忆入口"——用户的工作流上下文 = 浏览器拥有 = AI 时代的核心资产

2 · 用户场景洞察 & 痛点

基于 QB 历史调研 + 0618 用户行为分析

2.1 用户三大场景分布（PC 端）

历史调研：QB PC 端约 90% 用户集中在以下三大场景：

场景典型行为资产沉淀痛点
信息收集看资讯、查资料、做研究、追内容临时收藏太多、找不回来、用不起来
资源获取下视频、下文件、找模板下载完散落各处、复用率低
文件&事务处理看文档、写报告、做表格跨工作流的文件/网页/对话无法关联

2.2 阶段性资产 · 核心痛点

🎯 核心痛点

用户因临时工作流（短期项目、研究任务、决策对比）产生的"阶段性资产"，浏览器目前承接极弱：

  • ❌ 不想全存书签：怕积累冗余、编辑成本高、找不回来
  • ❌ 但又怕丢失上下文：关闭浏览器 / 切换设备就忘了"我刚才在干嘛"
  • ❌ 用户主动收藏后，AI 用不起来：收藏只是"存"，没有"用"的闭环
  • ❌ 多模态资产无处放：网页、文件、图片、AI 对话 各自孤立

2.3 真实场景举例（讲给汉博/陈颖）

📌 场景 A · 买车决策

用户花两周对比 5 款车：看了 30+ 网页、收了一些视频测评、和元宝聊过 2-3 次对比、下了几份报价单 PDF —— 这些资产现在散落在书签 / 历史 / 下载 / 元宝聊天记录 4 个地方，决策时根本拼不起来。

📚 场景 B · 学习资料

学生收集"机器学习入门"资料：知乎专栏 + GitHub 项目 + B 站课程 + PDF 论文 + 元宝梳理的笔记 —— 下次想复习，需要去 4 个入口翻找。AI 收藏夹 = 一站式资产箱。

💼 场景 C · 跨端汇报

用户白天在公司 PC 上整理了一组"行业研究"资料，晚上回家想用手机 / 平板继续看：书签同步可以，但行为层资产（停留时长、AI 对话、批注）丢失。AI 收藏夹 = 资产 + 行为同步。

🛍️ 场景 D · 临时清单

用户买年货：30 个商品页 + 5 张比价截图 + 几篇评测 —— 不想存书签污染收藏夹，又想保留到买完为止。AI 收藏夹 = 短周期临时存储 + 完成后一键归档/删除。

3.2 我们的 3 个差异化锚点

🥇 锚点 1

深度元宝整合

竞品 AI 能力多是"附加" → 我们 AI 收藏夹的资产 原生作为元宝助手的记忆库，问答时自动调用。这是 QB 独有的产品矩阵优势。

🥇 锚点 2

AI 自动整理

竞品全靠用户手动建文件夹 / 打标 → 我们一键智能打标 + 智能分组（已与 vance 算法链路打通）。用户零分类成本。

🥇 锚点 3

浏览器原生触手

竞品需要"切换 App / 复制粘贴"才能存东西 → 我们直接在浏览器内：悬浮球拖拽 / 划词右键 / 截图 / Ctrl+Space。零摩擦留痕。

💡 为什么用户会用我们而不用 Notion / Edge？

Notion 是"独立工具"——要主动打开 / 切应用；Edge 集锦只能存网页；微信星标只能链上传。AI 收藏夹长在浏览器里，是用户日常浏览的"原生留痕通道"——做的是"顺手"，不是"专门"。

4 · 产品定义

边界、形态、数据源

4.1 一句话定位（重申）

AI 收藏夹 = 用户「场景化资产沉淀池」
—— 在 PC 浏览器内提供 主动收集 / AI 整理 / 元宝调用 三位一体的工作台 ——
承接 Agent 时代用户「记忆入口」的争夺战。

4.2 三阵地边界（核心）

AI 收藏夹与浏览器已有阵地的关系，必须严格区分：

📚
书签管理器
网页 URL 树状管理
承载：仅 URL 关系：与 AI 收藏夹「书签 Tab」同一份数据 入口：完整保留
🌟
AI 收藏夹
主动收集 + AI 整理 + 元宝承接
承载：全模态资产 关系：主战场 入口：地址栏 / 悬浮球 / 顶部栏
📁
文件阵地（我的文件）
用户下载文件管理
承载：用户下载的文件 关系：不自动同步，需用户手动"加入 AI 收藏夹"晋升 入口：完整保留
📌 关键设计原则

「下载 ≠ 收藏」：用户下载文件是"我要这东西落本地"；用户收藏是"我觉得这东西有沉淀价值"。两件事不能混。这就是为什么文件阵地不自动同步到 AI 收藏夹。

4.3 数据源清单（一期 4 类）

#数据源来源动作与原阵地关系
1书签地址栏 ⭐ / Ctrl+D / 右键收藏 / 划词收藏到书签与书签管理器 双向同步
2文件「文件阵地」内点"加入 AI 收藏夹" / 拖拽进 AI 收藏夹页面引用方式存储，不自动同步
3网页元素右键图片/视频 → "收藏到 AI 收藏夹" / 划词 → "收藏摘录"独占
4AI 资产元宝助手对话内 → "沉淀此对话" / 用户保存常用 prompt独占（依赖 Geoffrey 自己提单加按钮）
💪 关键资源优势

"沉淀此对话"按钮 → 我有元宝助手内容权限可自己提单加 → 不依赖元宝团队排期 → MVP 落地强杠杆。

5.4 快存悬浮球（轻量化留痕）

🎯 设计目标

降低留痕门槛 → 让用户"想存就存、不想想就存"，覆盖主动 + 被动全场景。

5.4.1 触发与位置

  • 常驻位置：浏览器内右下角（默认） / 可调左下/顶部/侧边
  • 快捷键：Win Ctrl + Space / Mac Cmd + Enter 一键唤起
  • 鼠标行为：拖拽内容到悬浮球即存（默认 0s 触发，可调 0.3/0.5/0.7/1/3s）

5.4.2 支持的存储方式

方式对象触发
拖拽文字/图片/网页/标签组/文件拖到悬浮球即存
右键菜单图片/视频/链接/选中文字右键 → "收藏到 AI 收藏夹"
划词收藏网页正文文字选中文字后悬浮按钮一键存
截图网页区域调用 QB 截图工具 → 存入收藏夹
本地上传从桌面拖文件拖到 AI 收藏夹页面即存
地址栏 ⭐ / Ctrl+D当前网页原书签收藏路径，自动入库
元宝对话沉淀对话记录 + 关键 Prompt元宝助手对话 → "沉淀此对话"按钮

5.4.3 默认元数据（自动记录）

  • 保存时间
  • 来源 URL（如有）
  • 页面标题（自动抓取）
  • 缩略图（自动生成）
  • 设备信息（PC / 移动）

5.5 智能整理 · 仅作用于书签 Tab

🤖 工作流（已与 vance 算法链路打通）
  1. 用户勾选要整理的书签范围（base 文件夹）
  2. 已抽取的网页内容 → 模型 → 生成 tag_list（智能打标）
  3. tag_list + 用户 path 偏好 → 启发式分组（base 之下最多 4 层 = L1~L4）
  4. 预览结果 → 用户确认 → 落地
⚠️ 重要约束（与工程已对齐）
  • 结果默认预览：不直接覆盖用户原结构，用户确认后才落地
  • 30 天回收 + 撤销：兜底误整理，可一键回滚
  • 单次上限 1000 条：超过分批处理
  • 用户原结构尊重：一期不做，二期接入 path 复用

5.6 AI 能力调用 · 全部走元宝助手

💡 设计哲学

不自造 AI 能力——AI 收藏夹只负责"准备好资产"，AI 调用全部交给元宝助手承接：

  • ✅ 复用元宝已有的全部能力（总结/对比/PPT/思维导图/订阅）
  • ✅ 不重复造轮子，不和元宝产品打架
  • ✅ AI 收藏夹的资产 → 自动成为元宝的记忆库

5.6.1 调用入口

  • 右键单条资产 → "问元宝" / "总结" / "做PPT"
  • 多选 + 右键 → "对比/合并问元宝"
  • 整组资产（如某个标签下全部）→ "整组发给元宝分析"
  • 反向：元宝助手内问"我之前收藏的洗碗机对比" → 自动调出 AI 收藏夹相关资产

5.7 用户路径 · 4 步闭环

步骤动作关键体验
1. 标记悬浮球 / 右键 / 快捷键 / Ctrl+D3 秒内完成，零摩擦
2. 沉淀自动入 AI 收藏夹，AI 自动打标无需手动分类
3. 应用右键 / 多选 → 元宝助手承接AI 一键生成总结/PPT
4. 同步多端可见（移动端只读）跨设备无缝衔接

7 · 用户教育（轻量 A）

创新功能必答题：用户怎么知道"这个东西能做啥"？

7.1 用户教育的核心难题

⚠️ 真问题

AI 收藏夹是创新功能，用户没有现成心智可对标：

  • 用户看到"AI 收藏夹"四个字 → 第一反应是"和书签收藏夹有啥区别？"
  • 用户进入工作台 → 不知道悬浮球能拖拽 / 不知道能问元宝
  • 用户不主动用 = 不知道价值 = DAU 起不来

7.2 一期用户教育策略 · 轻量 A

A1 · 首次进入引导

用户首次打开 AI 收藏夹 → 5 步交互式 Tour：

  1. 这是你的资产工作台
  2. 左侧导航分类查找
  3. 试试拖拽这条文字到悬浮球（动手）
  4. 右键 → "问元宝"试试
  5. 恭喜，已经会用了！
A2 · 入口处 Tooltip

悬浮球 / 右键菜单 / 快捷键首次出现时，附带 1 句话提示：

  • 悬浮球："拖东西到这里就能存"
  • 右键："试试 AI 一键问元宝"
  • 快捷键 (Ctrl+Space)："秒存任何东西"
A3 · 帮助中心 + 案例展示卡

在 AI 收藏夹工作台空状态时展示4 个案例卡：

  • 📌 买车决策案例
  • 📚 学习资料案例
  • 💼 跨端汇报案例
  • 🛍️ 临时清单案例

用户点击 → 自动加载 demo 数据演示效果

A4 · 入口运营位

浏览器首页卡片 / 地址栏星标 hover / 元宝助手内 → 加运营条："✨ 试试 AI 收藏夹，让你收藏的东西真正有用"

8 · 副作用 & 风险

必须正面回答的"夺命问"

8.1 隐私风险

⚠️ 法务边界已对齐

参考前期咨询法务结论：

  • 暂态资产（标签页、临时浏览）= 隐私程度低 = 用户手动触发即可整理，但需告知规则
  • 恒态资产（书签、历史、文件）= 隐私程度高 = 需用户授权才能整理，可关闭授权退出
  • 本地优先：所有资产默认本地存储，云端同步需用户主动开启

8.2 用户认知负担

⚠️ 风险

7 个 Tab + 工作台 + 悬浮球 + 智能整理 + 元宝调用 = 功能多 → 用户懵

✅ 缓解
  • 首次进入引导（章节 7.2）
  • 默认列表态（最低认知成本）
  • Tab 默认仅显示有内容的，空 Tab 不强行 push
  • "智能整理"需用户主动点，不自动触发

8.3 性能风险

⚠️ 风险

资产量大（千+条）时，工作台加载慢、智能整理耗时长、跨设备同步压力

✅ 缓解
  • 列表/瀑布流均使用虚拟滚动（按需渲染）
  • 智能整理单次上限 1000 条，超过分批
  • 同步走轻量化 diff 机制，复用现有书签同步链路

8.4 数据源耦合风险

⚠️ 风险

书签 Tab 与书签管理器/浏览器顶部书签栏三位一体 = 一处改动可能影响三处

✅ 缓解
  • 统一数据 Schema，三个入口都 read-write 同一份
  • 测试覆盖：每个动作（增/删/改/移动）三处一致性自动校验
  • 灰度策略：新功能先小流量验证

8.5 与友邻产品的边界风险

⚠️ 风险

桌面整理（summer/lakin 主导）也在做"主动收纳" = 边界可能模糊

✅ 缓解
  • 明确分工：桌面整理 = 系统层（OS 文件） / AI 收藏夹 = 浏览器内主动收藏
  • 协同入口：桌面整理悬浮球 → "加入 AI 收藏夹"作为外部资产入口
