📌 TL;DR · 4 个最严重问题

  • ① 单书签叶组占比过高（5 个用户平均 70%）—— 模型在过度细分而非聚类，违反「整理 = 收敛」的核心目标
  • ② L1 出现大量语义重叠的兄弟组（"搜索"/"搜索引擎"、"娱乐"/"影视娱乐"、"新闻"/"新闻资讯"）—— 命名空间没有去重
  • ③ 同一书签被重复分到多个组（21 项重复 / 52 总书签 = 30%+）—— 应该是单一归属，不该一条多挂
  • ④ L1 数量爆炸（52 个书签输出 21 个 L1 / 217 个书签输出 14 个 L1）—— 原则应该是 5-10 个 L1，多了等于没整理

2问题 1 · 过度细分 · 单书签叶组占比 70%

🚨 现象：71% 的叶组里只有一个书签
5 个样本平均 70% 的最深一级分组只挂着 1 个书签。这意味着模型在做"为每个书签造一个分组"，而不是"把书签聚到同类组"。
具体例子（qbid=110ccacd04cec47b）：
• 上网导航 > AI 工具 > 游戏阅读 → 只有 1 个书签「上网导航」
• 上网导航 > 资源导航 > AI 工具游戏 → 只有 1 个「上网导航 - 轻快上网」
• 上网导航 > 资源导航 > AI 游戏阅读 → 只有 1 个「上网导航 - 轻快上网」
→ 一个"上网导航"网站被同时分到 3 条 L3 路径，且每条都自成一组。
💡 vance 的策略改进方向
叶组应有最小书签数阈值（建议 ≥ 2）。如果某叶组只有 1 个书签：① 上提到父级合并 ② 或者归入"其他/杂项"；不要为孤儿造一个分组。

2问题 2 · L1 命名重复 · 模型没有"已见过的命名"记忆

🚨 现象：同义/近义词在 L1 兄弟节点同时出现
模型在生成 L1 时没做去重，导致用户看到"两个看起来差不多但其实拆开的"分组——这是用户最容易吐槽"AI 整理还不如不整理"的点。
真实样例：
• qbid=110ccacd：上网导航 vs 网站导航、搜索 vs 搜索引擎、新闻 vs 新闻资讯、金融 vs 金融服务、电商业 vs 电商购物
• qbid=1121d1a1：IT服务 vs 信息服务 vs 网络服务、电商 vs 电商平台 vs 电商购物 vs 购物、视频 vs 视频平台
• qbid=1123df6b：娱乐 vs 影视娱乐、影视 vs 影视娱乐
💡 vance 的策略改进方向
L1 生成需要同义词归一步骤：① 生成候选 L1 后，用 embedding 相似度做聚合 ② 或者预设一个"标准 L1 词典"（购物 / 资讯 / 娱乐 / 工具 / 学习 / 影视 / 游戏 / 金融 / 系统等），强制对齐。

3问题 3 · 同一书签出现在多个分组

🚨 现象：1 个书签 → N 个不同 L1 / L2 / L3 路径
qbid=110ccacd 的 52 个书签中，有 16 项是重复出现（重复率 30%+）。整理的本质是"给每个书签找一个家"，不是"复制粘贴到所有可能匹配的家"。
具体例子：
• 「上网导航」被分到 4 条不同路径（搜索 / 上网导航 / 资源导航 / 网站导航）
• 「百度搜索」被分到「搜索 > 搜索引擎 > 百度搜索」和「搜索引擎 > 在线服务 > 资讯门户」
• 「头条新闻」被分到「新闻 > 头条新闻」和「新闻资讯 > 综合新闻」
💡 vance 的策略改进方向
硬约束：每个书签输入 ID 在输出树中只能出现 1 次。如果模型给了多个候选路径，取相似度最高的那条；其余路径不输出。

4问题 4 · L1 数量爆炸（用户看着像没整理）

🚨 现象：52 个书签产出 21 个 L1，564 个书签产出 26 个 L1
用户视角的"整理"= 把多变少。但模型输出 L1 数和输入书签数几乎成正比，说明模型在"分而不聚"。这个体感上的失败比单点错误更致命——用户打开看到 21 个组，第一反应是"我自己整理也是这样啊"。
建议的合理 L1 数：
• 输入 < 50 → L1 应在 3-5 个
• 输入 50-200 → L1 应在 5-8 个
• 输入 200-500 → L1 应在 6-10 个
• 输入 > 500 → L1 不应超过 10-12 个（需要 L2 / L3 承接细分）
💡 vance 的策略改进方向
L1 数量上限应该是软约束：① 模型先生成所有候选 L1 ② 按相似度合并到 ≤ 10 个 ③ 剩下的次优组下沉到 L2。不要让模型"想到一个新角度就开一个 L1"。

5给 vance 的优化优先级建议

优先级策略改进预期效果
P0叶组最小书签数 ≥ 2（孤儿上提或归"其他"）单书签叶组占比 70% → 20% 以内
P0书签输出唯一性约束（一个书签只挂一处）重复率 30% → 0%
P1L1 同义词归一（embedding 聚合 / 标准词典）语义重叠 L1 消失
P1L1 数量软上限（≤ 10）用户体感"AI 真的整理过"
P2层级深度上限 ≤ 3（base + L1 + L2 + 书签）不要 L4，浏览路径过深

📋 写在最后

这份观察基于 5 个样本的客观数据。P0 两条（孤儿组 + 重复书签）是结构性硬伤——人工评测时大概率拿 0 分。建议先解 P0，再迭代。
