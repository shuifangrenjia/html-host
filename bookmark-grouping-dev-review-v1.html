2. 产品强约束（建议本期接入）

① layer 改为相对 base，base 之下最多 4 层 必须

当前问题：技术文档里 layer1-4 没有明确"相对什么"。用户勾选的文件夹本身可能已在第 5/6 层（相对 root），如果工程把"layer1-4"理解为"绝对 root 下的层级"，会出现两种 case：
  • 用户勾选很深的子目录 → 工程不知道当前已经在第几层，无法判断 bound
  • "4 层"如果是相对 root，base 在第 5 层就触发不到分组逻辑
产品定义：
• layer 全部相对 base（用户勾选的根位置）
• base 之下最多再加 4 层（不管 base 相对 root 是几层）
• base 已是第 6 层 → 工程在第 6 层之下做 layer1-4 分组（相对 root 第 7-10 层）

② 打标 prompt 加入"命名规范化"约束 新增

当前风险：tag_list 直接当 group_path 的 layer 名 → 如果打标输出"AI平台"、"翻译工具与技术"等冗余命名，组名也跟着冗余，命名质量直接被测评扣分。
建议在打标 prompt 内显式约束：
  • tag 不带尾缀："平台 / 服务 / 网站 / 专题 / 分类 / 系统 / 工具与XX / XX与XX"（A+B 命名）
  • tag 字数：2-6 个汉字 / 1 个英文专有名词
  • tag 颗粒度：子层 tag 比父层更具体（如父层 "AI"，子层应是 "chatbot/绘图工具"，不是 "AI 模型"）
  • 避免泛化：不出现单独的"生活/工作/学习"作为子层 tag

③ 打标 prompt 加入"已有 tag 复用"约束 新增

当前问题：N-M 条已有 tag 的书签直接跳过打标流程，但 M 条新打标书签不会参考已有 tag → 同一类内容打出来的 tag 可能不一致（如老书签 "电商购物"，新书签变 "网购"）。
建议：M 条新打标书签的 prompt 中，传入同批 N-M 条已有 tag 列表作为参考词表：
  • 规则：相似内容/形式的网页，优先复用已有 tag，仅当确实没有合适的才生成新 tag
  • 例：用户已有 "电商购物" tag，新书签内容是"淘宝商品页" → 应输出 "电商购物"，不应输出 "网购/购物"

④ 单次整理书签数上限 = 1000 条 产品定义

依据（简要）：典型重度用户书签量约 500-2000 条。结合模型上下文限制（16K-32K）+ "分属打标助手(摘要版)" T2≤4 的批处理速度，1000 条对应约 12-15 分钟处理时长，覆盖 95% 以上场景。
超过 1000 条建议：① 报错提示用户分批 ② 或后台分批跑 + 进度显示。具体由工程评估。

3. 暂缓事项（二期再做）

用户已有结构尊重度（path 复用） 二期

用户原有书签结构（path）的复用方案有多种（提炼组名当 tag / 当 path_hint / 打标 prompt 传入参考），本期不做。先跑通通用链路，等一轮真实数据后再决定二期方案。
本期测评中此维度也不评测（满分按 4 维度 = 4 分计）。

4. 当前方案保留不动的（明确确认）

  • N-M-P 三段式打标流程 ✅ 合理
  • layer1-4 bound 默认值（20 / 10 / 5 / 999）✅ 不动，layer4=999 当不限处理是合理的
  • "应分尽分"原则 ✅ 即使某组只有 1 条也允许成组（产品确认接受）
  • 启发式合并 + 拆分助手 + 重命名助手 ✅ 合理
  • 摘要总结助手长文拆段拼接逻辑 ✅ 合理

5. 流程图（产品视角）

用户勾选 N 条书签（base = 用户勾选位置）
 ↓
① 已有 tag 的 N-M 条：直接进入分组阶段，tag 作为参考词表 →
② 新打标的 M 条：
  • P 条可爬正文 → 摘要助手 → 摘要版打标助手（T2≤4）
  • M-P 条仅有标题 → 标题版打标助手（T1<20）
  打标 prompt 内置：命名规范化 + 已有 tag 复用
 ↓
③ N 条全部进入分组：
  • layer 相对 base，最多 4 层
  • 每层 bound = 20 / 10 / 5 / 999
  • 超 bound 且未到 layer4 → 拆分助手 → 重命名助手
 ↓
输出：每条书签 group_path（最多 4 层，相对 base）
