AI NATIVE 浏览器 · 产品定位 v1

把浏览器藏在 AI 后面，
而不是把 AI 装在浏览器旁边

所有的双栏 · 工作台 · 侧边聊天框，
本质都还是 "浏览器 + AI 助手"。
AI Native 浏览器，应该让用户第一次打开就忘记浏览器的存在——
他只看到一个能听懂他的对话框。
1
一句话产品定义
PRODUCT DEFINITION
AI Native 浏览器 = 一个能听懂你意图的对话框 + 能替你做事的 Agent + 能记住你脑子里所有想法的 Memory。
USER MEMORY POINT · 用户记忆点
"这是一个和 AI 说话的浏览器。"
2
最大差异 · 旧浏览器 vs AI Native
✗ 浏览器 + AI 助手（当前稿）
双栏工作台
左对话框 / 右画布。用户要先理解"哪里是 AI、哪里是浏览器、什么场景用什么"。门槛高。
✓ AI Native 浏览器
一个对话框 + 渐进展开
首屏只有一个框。用户表达意图，AI 决定后续呈现什么。新用户 0 学习成本，重度用户解锁全能力。
✗ 入口是搜索/地址栏
用户主动 navigate
用户必须先知道"我要去哪 / 我要搜啥"。这是 30 年的旧范式。
✓ 入口是意图
用户表达"我想做什么"
用户说"帮我比一下这 3 家公司"，AI 自动跳 tab、抓数据、出表。意图 → AI → 结果。
✗ 记忆 = 收藏夹 / 稍后读
需要用户管理
用户要建文件夹 / 打标签 / 整理。这就是另一个 Notion，又一个负担。
✓ 记忆 = 被动吸收 + 主动召唤
不需要用户管理
AI 后台默默存 / 用户随时召唤。"管理"是负担，"召唤"才是产品。
3
三大设计原则
原则 1极简首屏 · 0 学习成本
新用户打开浏览器的前 3 秒只看到一个东西：居中的对话框 + 一句欢迎语。
没有 tab 栏、没有书签栏、没有侧边栏、没有"AI/搜索/网页"这种模式切换按钮。
用户只需要会一件事——打字或说话。
原则 2意图驱动 · 不是工具切换
用户表达意图，AI 决定后续呈现什么——
说"打开 X 网站" → 直接跳转
说"我想买车" → AI 给答案 + 推荐 + 沉淀到记忆
说"比一下 3 家公司" → AI 自动开 tab + 抓数据 + 出表
用户永远不需要选"我现在要用 AI 还是用浏览器"。
原则 3渐进展开 · 重度用户解锁深度
首屏极简，但用过几天后——
最近召唤过的记忆 / 正在跑的任务 / 推荐的内容流，
会自然出现在副视觉位（侧边 / 底部 / 卡片）。
新用户只看到第一层 / 重度用户拥有全部能力——同一个产品，两种密度。
4
汉博三模块 · 在新定位下怎么落
看得快 · 理解透 P2
不是产品形态创新点，是底层能力——必备但不是钩子。X 浏览器原班人马继续做。
有手有脚 P1
藏在意图后面，不是悬浮按钮 / 不是工作台模式。用户说"做 X"，AI 直接做完——执行不是入口，是结果。
用户："帮我看完这 3 家公司财报，给我一张对比表" → AI 自动跳 3 tab + 抓数据 + 出表 + 沉淀到记忆。用户全程不点任何"开启 Agent 模式"按钮。
记忆（智能收藏夹 + Trigger）P0 · 我的主战场
记忆是这个浏览器和别人最大的差异点。但用户不会管理它——只会"种"和"召唤"。
用户在浏览器里说"记一下" → AI 给自己留一颗种子。
一周后，他打开新 tab，AI 主动说："你上周种的 5 颗种子，可能在指向同一件事，要不要展开？"

"AI 真的懂我"——不是又一个稍后读、不是又一个收藏夹。
5
新用户打开浏览器的前 3 秒蓝图
FIRST 3 SECONDS

看到的：一个对话框 + 一句欢迎语。仅此而已。

  • 居中大对话框（占屏幕中部，参考 Arc Search / Spotlight）
  • 欢迎语："想做什么？告诉我就好。"
  • 没有 tab 栏 / 书签栏 / 历史栏 / 侧边栏
  • 没有 模式切换按钮（AI / 搜索 / 网页）
  • 顶部右上角：1 个隐藏的菜单按钮（重度用户用）

这一代 AI Native 产品的赢家全部走"对话框替代地址栏"。不是赌方向，是赌时机。
