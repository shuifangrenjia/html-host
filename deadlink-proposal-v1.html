1. 核心约束（不可妥协）

  • 用户体感"一次扫描"，不允许多次复扫
  • 少量误杀可接受，但必须有兜底机制（30 天回收 + 一键撤销）
  • 永久信号优先，永久信号即使指纹存在也照样清理

2. 双层判定架构

扫描每条书签
  ↓
第一层 · 指纹兜底：用户曾成功访问过 + 指纹匹配？
  ✅ → 保留（除非命中第二层永久信号）
  ↓
第二层 · 错误码判定：
  A 永久信号（410 / 451 / DNS NXDOMAIN）→ 进清理候选 直清
  B 强嫌疑（单次 404 / 5xx / 证书过期 / 连接失败 / 超时）→ 进清理候选 可清
  C 不判定（403 / ERR_BLOCKED_BY_ADMINISTRATOR）→ 保留 不动

3. 错误码档位表

信号档位处置
HTTP 410 Gone永久服务器明牌"我没了"，直接清理（指纹也不能挽救）
HTTP 451永久法律永久下架
ERR_NAME_NOT_RESOLVED
ERR_NAME_RESOLUTION_FAILED		永久一次扫描内并发查 3 个 DNS（114/8.8.8.8/腾讯）全失败 → 域名永久失效
HTTP 404（单次）嫌疑无指纹保护 → 进清理候选；有指纹 → 保留
HTTP 5xx嫌疑同上
ERR_CERT_DATE_INVALID嫌疑同上
ERR_CONNECTION_TIMED_OUT
ERR_CONNECTION_REFUSED
ERR_CONNECTION_RESET		嫌疑同上
HTTP 403不判权限/地域问题，页面活着
ERR_BLOCKED_BY_ADMINISTRATOR不判当前环境被企业策略拦截，不是页面失效
ERR_INTERNET_DISCONNECTED
ERR_NETWORK_CHANGED		不判用户本地网络问题，跳过本次扫描

4. 指纹机制（依赖晓航方案）

用法

  • 指纹库提供查询接口：传入 URL → 返回（是否有指纹 / 历史指纹值）
  • 判定时，对当前扫描页面算一次指纹 → 与历史指纹比对
  • 匹配 → 保留；不匹配或无指纹 → 走错误码判定

边界

  • 动态页面（淘宝商品/微博 feed）—— 内容指纹不可用，按域名加白名单
  • 新用户/冷启动—— 指纹库为空，完全依赖错误码
  • 永久信号优先—— 410 / 451 / DNS 永久失败 即使指纹匹配也照样清理

5. 误杀兜底（必须有）

三层防线，缺一不可
  • 清理项不直接删，移到"已清理"回收文件夹
  • 回收文件夹保留 30 天，到期才真正删除
  • 每条清理项显示判定原因（"HTTP 404 找不到页面" / "域名失效" / "证书过期"），用户能看懂为什么
  • 顶部提供"撤销全部"按钮，一键恢复

6. 上线策略

  • 建议先灰度 1%-5% 用户跑 1-2 周，观测投诉率
  • 核心指标：误杀率（撤销率/总清理数） < 3% 才放量
  • 埋点：清理候选数 / 用户实际确认清理数 / 撤销数 / 投诉数

7. 待晓航确认（关键依赖）

问题 1：指纹库当前对书签 URL 的覆盖率多少？（直接决定误杀率）
问题 2：动态页面（淘宝/微博/抖音）有没有黑名单？指纹方案怎么处理？
问题 3：指纹查询接口的 QPS 上限？（一次扫描可能批量查上千 URL）
问题 4：永久信号即使指纹存在也清理 —— 这条规则你那边能接受吗？
