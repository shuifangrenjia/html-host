死链判定 · 一次讲明白

@AI产品Geoffrey · 给自己 / 给晓航 / 给研发同步用 · 2026-05-18

1. 死链是什么？

书签里那条 URL，用户今天点开打不开了。原因可能很多种，大致两类：

临时打不开

站在那儿，但今天家里没人

明天后天可能又能开

永久没了

房子已经被拆了

明年也不会回来

👉 我们要清理的只能是右边那种。清错了左边的 = 用户投诉。

2. Chrome 错误码 · 浏览器的"诊断报告"

类比：你按门铃没人开
浏览器去访问网址，就像你上门按门铃。
门铃响了 → 没人开（超时）
门牌号查不到 → 找不到这家（DNS 失败）
门口贴条"本户已搬走"→ 410 Gone
门口写"本房屋租赁合同到期"→ 404

Chrome 浏览器内核内置了 231 个错误码，每个对应一种"失败原因"。我们的工作是：挑出来哪些错误码代表"房子真的拆了"，哪些只是"今天没人开门"。

能直接判"永久没了"的（很少）

  • HTTP 410 —— 服务器主动告诉你"这页面我永久删了"（明牌）
  • DNS NXDOMAIN —— 域名压根不存在了（房子地址都没了）
  • HTTP 451 —— 法律原因下架（被强拆了）

不能直接判（很多）

  • 超时 / 连接失败 —— 可能服务器临时挂了
  • 5xx —— 服务器闹毛病，不是"没了"
  • 单次 404 —— 可能临时维护下架
  • 403 —— 你没权限，但页面活着

3. 网页指纹 · 给网页发"护照"

类比：你护照上的证件照
你 10 年前办的护照，照片是当时拍的。
10 年后过海关，海关掏出你的护照对照片 —— "嗯，这人是你"。

网页指纹同理：用户 3 个月前**成功**访问过某个网页，浏览器把当时的网页"长什么样"存了一份照片（指纹）。
今天再访问 → 拿当下页面对一下指纹 → 对得上，是同一个网页 → 还活着。

指纹是怎么"拍照"的？

1
用户成功访问一次网页
2
浏览器把页面的关键特征提取出来：URL + 页面标题 + 正文摘要 hash + 关键 DOM 结构
3
这一串特征值 = 这个网页的"指纹"，存在用户本地或云端
4
下次扫描时，对当前页面再算一次特征 —— 对得上 = 网页还是那个网页

为什么需要指纹？

真实场景：用户书签里有一篇 5 年前的博客文章。
今天扫描 —— 服务器返回 503（临时维护）。

只看错误码：可能误判为"挂了"想清理。
有指纹兜底：3 个月前用户成功访问过，指纹存在 —— "这页面用户认得，先别动"。

指纹的核心价值：用"用户曾经认可过"作为防误杀的最后一道闸。

4. 错误码 + 指纹 · 双层判定

类比：法院判决
错误码 = 物证（房子拆了的照片）
指纹 = 人证（邻居说"以前住过人"）

要判一个房子"永久不存在"，物证最强（明牌的 410/451/DNS失败）就直接判。
物证不够（404/超时/5xx），就靠人证（指纹）兜底 —— 邻居说住过人，那就先不动。

但指纹不是万能的

  • 动态页面（淘宝/微博）—— 每次刷新内容都不一样，指纹永远对不上 ❌
  • 新用户 —— 没访问过，指纹库是空的 ❌
  • 服务器明牌说没了（410）—— 即使指纹存在也照样清理（房主自己说房子拆了，不能因为邻居说有就保留）✅

5. 一句话总结

错误码看"网页在不在"，指纹看"用户认不认"。两者互补，永久信号优先。
